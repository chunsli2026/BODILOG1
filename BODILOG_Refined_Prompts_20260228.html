PROMPT 3  Image Segmentation & Processing Service

This prompt generates the service that takes the captured JPEG from Prompt 2 and segments it into four sub-images for downstream analysis.

 

Full Prompt Text

Create image_processing_service.dart that segments the captured urine test JPEG into four sub-images using fixed pixel coordinates, after normalising the image to a reference resolution.

 

Input

•        Full captured JPEG image from the camera module (variable device resolution, consistent 4:3 aspect ratio)

 

Processing Pipeline

7.      Load the JPEG using the image package

8.      Normalise to the reference resolution of 1080 x 1920 pixels using bilinear interpolation before any coordinate-based extraction

9.      Extract the four sub-images defined below using the normalised coordinates

10.   Return all four as a single ImageSegments result object

 

Sub-image Definitions (all coordinates are on the 1080x1920 normalised image)

 

Sub-image 1 — Barcode

•        Coordinates: top-left (10, 10) to bottom-right (920, 120)

•        Purpose: identify manufacturer, product model, batch number, and expiry date

•        Processing: convert to grayscale, then decode using google_mlkit_barcode_scanning

•        Output: BarcodeData object with fields: manufacturer, model, batchNumber, expiryDate, status (enum: decoded / unreadable)

•        On decode failure: do not throw; set status = unreadable and continue pipeline

 

Sub-image 2 — RGB Calibration Bar

•        Coordinates: top-left (20, 130) to bottom-right (120, 900)

•        Purpose: correct for ambient lighting and camera colour shift

•        Contents: three equal-height colour squares stacked top to bottom — Blue (#0000FF), Green (#00FF00), Red (#FF0000)

•        Processing: divide the sub-image into three equal regions; for each region sample a 20 x 20 pixel patch from its centre; compute the average RGB value of that patch

•        Output: CalibrationData object containing three measured RGB triples and three correction-factor triples (ratio of expected to measured value per channel)

•        Validation: if any measured channel deviates more than 20% from its expected value, set CalibrationData.status = unreliable and surface a CalibrationException to the caller, prompting a recapture

 

Sub-image 3 — Test Strip

•        Coordinates: top-left (130, 130) to bottom-right (920, 900)

•        Purpose: extract the colour of each of the 10 test pads

•        Processing: divide the sub-image into 10 equal-height horizontal regions (pad 1 at top, pad 10 at bottom); for each region sample a 50 x 50 pixel patch from its centre; compute the average RGB; apply the CalibrationData correction factors

The 10 pads map to parameters in order (top to bottom):

Sub-image 4 — Lookup Reference Matrix

•        Coordinates: top-left (10, 910) to bottom-right (920, 1910)

•        Layout: 10 columns (one per parameter) x 7 rows (one per possible result grade)

•        Cell size: approximately 91 x 143 pixels per cell

•        Processing: divide into a 10 x 7 grid; for each cell sample a 20 x 20 pixel patch from its centre; compute the average RGB

•        Output: LookupMatrix object — a 2D array [10][7] of RGB triples

PROMPT 6  Parkinson's Tremor Analysis (Wearable Sensor)

Parkinson's tremor detection is scoped as its own prompt due to the signal processing complexity involved. It depends on the WearableSensorDevice raw accelerometer stream established in Prompt 5.

 

⚠ CRITICAL: This module must NOT be merged into Prompt 5. If given together, the AI will produce a shallow implementation of both. Prompt 5 must be completed first.

 

Full Prompt Text

Implement tremor_analysis_service.dart for the BodiLog app to detect and score Parkinson's disease-related rest tremor from wearable sensor data.

 

Input

•        Raw accelerometer stream from WearableSensorDevice.subscribeToNotifications() at a minimum sample rate of 50 Hz

•        A configurable analysis window of 10 seconds (500 samples at 50 Hz)

 

Signal Processing Pipeline

20.   Receive raw triaxial accelerometer samples (x, y, z) as a Stream<AccelerometerSample>

21.   Buffer samples into a rolling 10-second window

22.   Apply a Butterworth bandpass filter (3–7 Hz) — the clinically recognised frequency range for Parkinson's rest tremor

23.   Compute signal power in the 3–7 Hz band using FFT (Fast Fourier Transform)

24.   Compute signal power in the 1–20 Hz band as the total reference band

25.   Calculate tremor ratio: power(3–7 Hz) / power(1–20 Hz)

26.   Apply a rolling average across the last 6 windows (60 seconds) to smooth the score

Tips for AI Code Generation

General Advice

•        Submit prompts one at a time. Do not combine multiple prompts in a single session.

•        At the start of each new prompt, paste in the relevant output files from the previous prompt as context.

•        After receiving generated code, ask the AI to also generate unit tests for each service class.

•        Review all hardcoded UUIDs and replace with your actual BLE device service/characteristic UUIDs before testing on hardware.

 

Dependency Version Conflicts

Flutter dependencies can conflict. If the AI generates code that uses APIs incompatible with the specified versions, ask it to:

•        Run flutter pub outdated to identify conflicts

•        Resolve by pinning the conflicting package to a compatible version

•        Prefer the version constraints specified in Prompt 1 as the source of truth
